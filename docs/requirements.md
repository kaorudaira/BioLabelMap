# 昆虫標本ラベル記録アプリ 要件定義書

Oct 2, 2026 · @yoshihara

## 1. 目的と範囲

圏外の山間部でも、GPSで採集地点を記録し、標本ラベルの印刷とデータ管理までを1台のスマートフォンで完結させる。対象OSはiPhoneとAndroid。参考はジオグラフィカ、スーパー地形。

基本フロー:

1. 地図を開くと、現在地とGPS精度(±m)が表示される
2. 「記録」ボタン、または地図の長押しでピンを立てる
3. 緯度経度、標高、地名、日時が自動入力される
4. 採集方法などを追記して保存する(種名は後から入力可)
5. 帰宅後に同定し、ラベルPDFとCSVを出力する

初期リリースの対象外:クラウド同期、複数端末での番号管理、CSVインポート、トラップ管理、QRコード、GeoJSON/KML出力。

## 2. 技術構成

Flutter(Dart)で、iPhoneとAndroidの両方に対応する。オフラインが最重要要件のため、記録から保存、PDF出力までを端末内で完結させる。

| 項目 | 方針 |
| --- | --- |
| フレームワーク | Flutter(Dart) |
| データ保存 | 端末内SQLite(Drift) |
| 地図 | flutter\_map+地理院タイル(範囲指定で端末に保存) |
| PDF出力 | マクロンと日本語の両方に対応したフォントを同梱 |
| 同期 | 当面なし。将来、Javaサーバーを追加できる余地を残す |

開発機はWindows。iPhoneのビルドにはMacが必要なため、クラウドのビルドサービスを使い、配布にはApple Developer登録(年額)が必要。

| F-19 | オフライン地図 | 第7章を参照 |

## 4. データ定義

1標本=1レコード。各標本に同定履歴が複数ぶら下がる。項目名は将来のGBIFなどへの出力を見据え、Darwin Coreに寄せる。測地系はWGS84固定。

| 区分 | 項目 | CSV列(Darwin Core) |
| --- | --- | --- |
| 地点 | 国 | country |
| 地点 | 県・市町村、地名(和・英) | stateProvince, county, locality |
| 地点 | 緯度経度 | decimalLatitude, decimalLongitude |
| 地点 | 精度 | coordinateUncertaintyInMeters |
| 地点 | 標高 | minimumElevationInMeters |
| 地点 | 測地系 | geodeticDatum |
| 採集 | 採集日(期間可) | eventDate |
| 採集 | 採集者 | recordedBy |
| 採集 | 採集方法(英語名) | samplingProtocol |
| 採集 | 環境・寄主植物 | habitat |
| 標本 | 標本番号 | catalogNumber |
| 標本 | 個体数(1固定)、性別 | individualCount, sex |
| 標本 | メモ、写真、印刷状態 | occurrenceRemarks ほか |
| 同定 | 属・種・亜種 | scientificName |
| 同定 | 命名者・年 | scientificNameAuthorship |
| 同定 | 同定者、同定日 | identifiedBy, dateIdentified |
| 同定 | 状態(未同定/仮同定/同定済み) | identificationVerificationStatus |

和名は `vernacularName` に出力する。CSV列の最終形は、実装時に確定する。

## 5. ラベル・印刷要件

標本1個体につき、3種類のラベルを出力する。

| 種類 | 内容 | 印刷タイミング |
| --- | --- | --- |
| データラベル | 採集地・標高・座標・日付・採集者 | 採集後 |
| 同定ラベル | 和名・学名・命名者・年 | 同定後 |
| コレクションラベル | `KYC00123` の1行のみ。データラベルと同じ4〜5pt。将来のQR用に余白を確保 | 採集後 |

**データラベル**

`{国}: {県_英}, {郡_英}, {市町村_英}, {地名_英}, (alt. {標高} m), {緯度}°N {経度}°E, {日}. {月_ローマ数字}. {年}, {採集者_英}, {郡_和}{市町村_和}{地名_和}`

例:JAPAN: Niigata-ken, Uonuma-shi, Shimooritate, (alt. 1390 m), 36.9447°N 139.2426°E, 20. VI. 2026, K. YOSHIHARA, 魚沼市下折立

例(郡あり):JAPAN: Niigata-ken, Minamiuonuma-gun, Yuzawa-machi, Tsuchidaru, (alt. 700 m), 36.8834°N 138.8205°E, 5. VII. 2026, K. YOSHIHARA, 南魚沼郡湯沢町土樽

- 県・郡・市町村の英語表記は、自治体コードから内蔵の対応表で自動変換する。対応表は総務省「全国地方公共団体コード」と日本郵便の郵便番号データ(ローマ字)から作る(`tools/municipalities/`)。綴りは日本郵便に従い(ン は b・m・p の前で m:Gumma-ken)、長音はカナからマクロンを補う。ただし、語の境目の母音の連続は長音にしない(ローマ字のつづり方〔令和7年内閣告示第4号〕では、長音で発音されるものだけを長音とする)。日本郵便は境目の母音も1文字にまとめるため、該当する28件(勝浦=Katsuura、豊岡=Toyooka、瀬戸内=Setouchi など)は `tools/municipalities/overrides.json` で直している
- 大字のローマ字は、次の順で決める。①手入力した値、②辞書(これまでに手入力した綴り)、③内蔵の対応表。対応表はデジタル庁「アドレス・ベース・レジストリ」(町字マスター)と日本郵便の郵便番号データ(ローマ字)から作る(`tools/municipalities/build_oaza.dart`)。綴りは公的データに従い、2つのデータで綴りが違うときは読み(カナ)と合うほうを採る。長音は県・市町村と同じくカナからマクロンを補う。ただし、末尾が `chō` の大字は、直前にハイフンを入れ、マクロンは残して `-chō` にする(例:Tondenchō → Tonden-chō)。対応表を引くときに変換する(手入力した値と辞書は変えない)。マクロンを含むので、これまでどおり確認が要る
- 語の境目か長音か判断が分かれる自治体名(雄武町 Ōmu-chō、邑楽郡・邑楽町 Ōra、青梅市 Ōme-shi、久遠郡 Kudō-gun)は、長音で表記する。自動入力のときは、記録画面(S-02)の地名の下に注意を出す
- 公的データは長音を省いて書くため、語の境目の「oo」「ou」も長音とみなされる(丸の内=MARUNOCHI、下折立=SHIMORITATE)。そのため、マクロンを含まない綴り(例:Tsuchidaru)は自動で入れ、マクロンを含む綴り(例:Shimōritate)は候補として示し、確かめてから入れる。確かめて直した綴り(例:Shimooritate)は辞書に入り、以後はそれを使う
- 記録時に入れられなかったときは、ラベル出力(S-07)で入力する
- 出典:アドレス・ベース・レジストリは CC BY 4.0。設定画面に出典と加工した旨を記載する
- 和文地名は県名を省き、郡(町村のみ)+市町村+大字
- 改行するのは、1行目(JAPAN: 県)の後、詳細住所(郡, 市町村, 大字)の最後、標高、緯度経度、日付と採集者の後。詳細住所はひと続きで書き、幅に収まらないときだけ改行する。詳細住所が3行以上になるときのみ、詳細住所の最後の改行を省き、標高を続ける(例:`…, Kanoseshimonoyamaishido, (alt. 700 m)`)。最後に日本語地名を置き、全体で最大7行とする
- 文字サイズは、1行目(JAPAN: 県)が4pt、詳細住所・標高・緯度経度・日付と採集者が3pt、日本語地名が3.5pt。標高を詳細住所に続けた行は、詳細住所の文字サイズにする。各項目の終わりのカンマは省く。フォントはFira Sans Condensed(日本語は別フォント)
- 枠からはみ出さないよう、余裕をもって改行する(使える幅の90%を超える前に改行)。区切りは「, 」を優先し、次に空白、最後にハイフンの後ろ。幅に収まらず改行したときは、行末のカンマを残す(例:`Minamiuonuma-gun,` / `Yuzawa-machi`)
- 1行目(JAPAN: 県)は改行せず、入らない県だけ文字を1段階(3.5pt)小さくする。Fira Sans Condensed の寸法で測ると、Kagoshima-ken、Yamanashi-ken、Kumamoto-ken、Yamaguchi-ken、Tokushima-ken、Fukushima-ken、Wakayama-ken、Hiroshima-ken の8県が該当する
- 日付と採集者が1行に収まらないときは、日本語の地名を印字しない。文字を小さくする処理より前に判定し、ラベル出力(S-07)で省いてよいか確認する。省かないことを選んだときは、通常の割り付けにする
- 日本語の地名は改行しない。1行に収まらないときは、一番大きい行政区画から省いて収める(郡 → 市町村の順。例:南魚沼郡湯沢町土樽 → 湯沢町土樽)
- 改行した結果7行に収まらない、または日本語の地名が大字だけでも入らないときは、詳細住所(郡と市町村・大字・日本語の地名)の文字を1段階(0.5pt)小さくする
- 1段階小さくしても収まらないときは、日本語の地名を省く。その場合はラベル出力(S-07)で警告し、省いてよいか確認する。省かないことを選んだときは、はみ出しの警告を出す
- 採集方法・環境はラベルに出さず、データとCSVにのみ含める
- 標本番号はデータラベルに印字しない。コレクションラベルで実物とデータを対応させる

* 期間(トラップの設置〜回収など)は、ハイフンでつなぎ、前後にスペースを入れない。同じ月は `19-20. VI. 2026`、月をまたぐときは `30. V.-2. VI. 2026`、年をまたぐときは `30. XII. 2025-2. I. 2026`。1日のみは `20. VI. 2026`
* CSVの `eventDate` には、ISO形式の期間(例:`2026-06-19/2026-06-20`)を出力する

**同定ラベル**

`{和名} {学名} {命名者・年}` det. {同定者}(例:スゲハムシ *Plateumaris sericea* (Linnaeus, 1761))

- 学名部分のみ斜体
- 命名者・年は、括弧の有無を含めて入力どおり保持する(自動で付け外ししない)
- 命名者と年の間はコンマ入りが既定(例:`Lewis, 1883`、`(Linnaeus, 1761)`)。甲虫の目録もこの表記
- 和名は任意

* 同定者名を記載する。新規の同定では、最後に入力した同定者名を既定で自動入力し、編集できる
* 同定者名が空の場合は、`det.` ごと省略する

**ローマ字表記**

- 長音はマクロン付き(例:Tōkyō-to、Ōsaka-fu、Hyōgo-ken、Hokkaidō)
- 入力補助として ō ū Ō Ū ボタンを置く
- 「oo」「ou」は変換候補を出すだけで、自動置換しない(例:大岡=Ōoka)
- ii・eiはそのまま表記する
- PDFフォントは、マクロンと日本語の両方に対応したものを使う

**印刷**

- 印刷単位を選択:「データ+コレクション」「同定のみ」「3種すべて」
- 並べ方を切り替え:標本ごとに3枚並べる(取り違え防止)/種類ごとにまとめる
- 同地点・同日の複数標本は、同じデータラベルと連番のコレクションラベルを並べて出力する
- 印刷済みを記録し、「未印刷のみ印刷」ができる
- ラベルPDFには地図を載せない

## 6. 採集方法プリセット

採集方法は選択式とし、トラップ系だけ設置〜回収の期間を入力する。CSVには英語名も出力する。

| 採集方法 | 英語名(CSV) | 区分 | 追加項目 |
| --- | --- | --- | --- |
| 任意採集 | General collecting | 任意 | なし |
| ルッキング | Looking | 任意 | なし |
| スウィーピング | Sweeping | 任意 | なし |
| 外灯 | At street light | 灯火 | なし |
| ライトトラップ | Light trap | トラップ | 光源、設置〜回収日 |
| ライトFIT | Light FIT | トラップ | 光源、設置〜回収日 |
| バナナトラップ | Banana trap | トラップ | 設置〜回収日 |
| ピットフォールトラップ | Pitfall trap | トラップ | ベイト有無・種類、設置〜回収日 |

- 選択肢は設定で追加・並べ替えできる(ビーティング、シフティングなど)
- 当てはまらない場合に備え、「その他(自由入力)」を置く
- 環境・寄主植物は、自由入力+履歴候補で入力する

## 7. オフライン地図要件

山間部の圏外でも地図を使えるよう、範囲を指定して地理院タイルを端末に保存する。

- 地図上で矩形を指定して「この範囲を保存」する。名前を付けて複数登録でき、削除もできる
- ダウンロード前に、タイル枚数と容量の見積もりを表示する。モバイル回線では警告を出す
- 各地図の最大ズームまで保存できる。保存時に最大ズームを選び、既定は16。上限は地図ごとに自動で決まる
- 保存範囲を超えてズームしたときは、最大ズームの画像を拡大して表示する
- 1エリアの上限は既定200MB。全体の上限とともに、設定で変更できる。超える場合は、範囲を狭めるかズームを下げるよう案内する
- 保存から半年たったエリアは、再取得を促す

容量の目安(約20km四方、標準地図、1タイル約20KBとして概算):

| 最大ズーム | 枚数 | 容量 |
| --- | --- | --- |
| 16 | 約2,300枚 | 約50MB |
| 17 | 約9,000枚 | 約180MB |
| 18 | 約36,000枚 | 約720MB |

各地図の最大ズームは、標準地図・淡色地図・写真が18、陰影起伏図が16、色別標高図が15(地理院タイル一覧で確認済、2026年10月)。

**利用規約**

- 地理院タイルは無償で利用できる。「国土地理院」「地理院タイル」の表記が必要。出典は地図画面に常時表示する
- 加工して利用する場合は、出典とは別に、加工したことを記載する。標高APIの値を加工して使う場合は、設定画面などに記載例に沿った表記を置く
- 不特定多数に提供しない間は、出典の明記で足りると判断して進める(国土地理院の資料 https://www.gsi.go.jp/common/000223838.pdf による。2026年10月、開発者の判断)。一般に公開・配布するときは、タイルの端末保存の可否と取得量を、国土地理院に問い合わせて確認する(文面は `docs/gsi_inquiry.md`)
- 対策として、範囲とズームの上限を設け、並列数を絞って低速で取得する

**実装の取り決め**(段階2)

- 保存するズームは6から最大ズームまで(広域は粗く、狭域は細かく持つ)。枚数と容量はこの全ズームの合計で見積もる
- 見積もりの1タイルの大きさは、標準地図20KB、淡色15KB、写真50KB、陰影起伏25KB、色別標高20KBの概算(実測ではない)。複数の地図を選んだときは合計する
- タイルは、エリアごとのフォルダ(`offline_tiles/area_<id>/<地図>/<z>/<x>/<y>`)に置く。重なるエリアは重複して持つ(エリア単位で容量を数え、削除をフォルダごとで済ませるため)
- 地図は、保存済みのタイルを先に読み、なければ通信で取る。圏外で保存範囲の外は灰色になる
- 取得は並列4・1枚ごとに50msの間隔(段階2の試用で、並列2・150msでは遅かったため引き上げた)。地理院にないタイル(404)は保存せず、取得済みとして数える。通信できなくなると止まり、「再開」で保存済みを飛ばして続きから取る。取得を始めるとき、前回残った一時ファイル(`.tmp`)を消す
- 「バックグラウンドでも続ける」は、アプリが動いている間(別の画面や他のアプリに移っても、OSに終了されない間)。OSに終了されたときは、一覧の「再開」で続ける
- Android の自動バックアップには、タイルを含めない(再取得できるため。端末内の簡易バックアップ(F-17)にも含めない)
- 1エリア200MB・全体1GBの上限は、段階4の設定画面ができるまで固定

## 8. 非機能要件

- **オフライン動作(最重要)**:圏外で、記録、保存、ラベルPDFの出力まで完結する。圏外で取得できない標高と地名は、通信復帰時に補完する
- **データの保全**:保存は即時に行う。アプリが強制終了しても、データが残る
- **バックアップ**:全データをファイルにエクスポートできる。端末の故障や紛失に備える
- **性能**:数百件の地点でも、ピンをまとめて表示し、地図が重くならない
- **操作性**:屋外の片手操作を想定し、主要な操作は大きなボタンで行う
- **入力欄**:すべての入力欄に、右端に入力内容をクリアする「×」を付ける(入力があるときだけ出す)
- **番号管理**:当面は1台の端末のみで採番する。クラウド同期に対応する際は、番号予約方式を検討する
- **対応環境**:iPhoneとAndroid
- **出典表示**:地図画面に、地理院タイルの出典を常時表示する

**S-02 記録画面の項目**

画面は上から次の順に並べ、保存ボタンは画面下に固定する。必須なのは位置と日時だけで、どちらも自動入力される。圏外でも、「記録」と「保存」を押せば記録できる。

1. **地点(自動)**:緯度経度、精度(±m)、標高、地名(和・英)。地名は編集できる。標高と地名が未取得のときは「取得待ち」と表示する。精度が±30mを超えると警告する。座標をタップすると小さな地図が開き、十字を合わせて位置を補正できる。補正すると精度の表示は「手動」に変わり、CSVの coordinateUncertaintyInMeters は空にする。標高と地名は補正後の位置で取り直し、圏外のときは補完待ちに入る
2. **日時(自動)**:採集日。「期間」に切り替えると、開始日と終了日を入力できる
3. **採集方法(選択)**:プリセットから選ぶ。トラップ系を選ぶと、光源、ベイト、設置〜回収日の欄が出る
4. **環境・寄主植物(任意)**:自由入力。履歴候補が出る
5. **標本(任意)**:作成数(既定1)、性別、メモ、写真。「番号を指定」のスイッチを入れると、開始番号を入力できる(過去標本の登録用)。重複は、ごみ箱の中も含めて保存前に警告する。指定した番号が自動の次の番号より大きいときは、次の番号をその続きに進める
6. **同定(任意)**:折りたたんでおく。和名、学名、命名者・年、同定者を入力できる

保存ボタンは2つ置く。「保存」は保存して地図に戻る。「保存して同地点で追加」は、地点・日時・採集方法・環境をコピーして新しい記録を開く。入力した状態で画面を閉じるときは、「下書きに保存」「破棄」「続ける」の確認を出す(何も入力していなければ、確認せず閉じる)。番号は、保存したあとに確定の操作で付けるので、記録画面には「番号は確定時に決まります」と表示する(第14章)。

1標本=1レコードなので、入力するのは「作成数」とし、各レコードの個体数は1に固定する。作成数が2以上のときは、標本番号を連番で生成する。

**画面の色分け**:項目の種類を4色で分ける。青は地点・日時(自動入力)、オレンジは採集(方法・環境)、紫は標本、赤紫は同定。記録画面では、各ブロックの左に太い帯を付け、背景を薄く塗る。標本詳細、標本一覧、ラベル出力でも、同じ4色を使う。選択中のボタンは、そのブロックの色で塗る。

**S-03 地点詳細の項目**

ピンをタップして開く。「どの虫を、いつ採ったか」が上から読める順に並べる。

1. **ヘッダー**:地名(和・英。英語は県から順に)、緯度経度(`36.94471°N 139.24258°E`の形。南緯・西経は°S・°W)、標高。標本の件数と、採集日の範囲(例:15件、2026/6/19〜20)
2. **標本の一覧**:種や採集日などが同じ標本を1行にまとめ、次の順に表示する
   - 種名:和名と学名。未同定のときは「未同定」
   - 採集日:年も付ける。期間のときは「2026/6/19〜20」
   - 採集方法:「その他」で自由入力があるときは「その他：{自由入力}」
   - 件数と標本番号(例:×3、KYC00120〜122)
3. **並び替え**:「日付順」(既定、新しい日から)と「種ごと」を切り替える

行をタップすると、標本詳細(S-05)を開く(標本が2件以上の行は、開く標本を選ぶシートを出す。シートの各行の右端に、その標本だけを編集するボタン、見出し「種名 ×件数」の右に「全てまとめて編集」(行の全標本の一括編集)と「選んで編集」(標本を選んで一括編集)を置く)。上部の「選択」ボタンで選択モードに入り、行の標本をまとめて、または展開して1件ずつ選んで、同定を追加・ラベル出力・一括編集・番号確定・削除ができる(標本一覧 S-04 と同じ操作)。下部の「この地点で追加」ボタンは、地点・日時・採集方法をコピーして記録画面(S-02)を開く。環境・寄主植物と写真は、標本詳細で表示する。データは、1標本=1レコードのままとする。

**S-04 標本一覧の項目**

S-03と同じく、種や採集日などが同じ標本を1行にまとめる。

- **1行の内容**:種名(和名と学名、未同定は「未同定」。同定済みは和名の左に緑のチェックマーク、仮同定は三角の中にビックリマークを付ける。状態が違う標本は別の行にする)、採集日・地名、採集方法、件数と標本番号(例:×3、KYC00120〜122)。未印刷の標本にはマークを付ける
- **行の区切り**:行と行の間に区切りの線を入れる。学名はイタリック体で表示する
- **並び**:採集日の新しい順が既定。標本番号順、種ごと、場所順に切り替えられる
- **検索**:種名、地名、標本番号
- **絞り込み**:採集日の範囲、地名、採集方法、同定状態(未同定/仮同定/同定済み)、印刷状態(未印刷のみ)。絞り込み中は、条件を画面上部に表示する
- **複数選択**:上部の「選択」ボタンか、行の長押しで選択モードに入り、画面下に操作を表示する。行をタップすると、その行の標本をまとめて選ぶ。2件以上の行は、右の「▼」で展開すると、標本を1件ずつ選べる(5件の行から2件だけ、など)。一部だけ選んだ行は、チェックを「半分」の表示にする。上部の「全て選択」で、表示している標本をすべて選ぶ。地点詳細(S-03)でも、同じ操作で選べる
  - ラベル出力:選んだ標本でS-07を開く
  - 一括編集:地名・採集方法をまとめて修正
  - 同定を追加:選んだ標本に同じ種名をまとめて入力
  - 番号確定:番号が未確定(仮)の標本に、番号を付ける(第14章)
  - 削除:ごみ箱に移す
- **ごみ箱**:削除した標本はごみ箱に残し、期間内なら元に戻せる。期間が過ぎると完全に削除する。完全に削除した番号は欠番とし、再利用しない。標本番号の重複チェックは、ごみ箱の中も対象にする

* **ごみ箱の入口**:標本一覧の右上のメニューから「ごみ箱」を開く。削除した標本が削除日の新しい順に並び、各行に「あと◯日で完全に削除」と表示する。行を長押しして選ぶと、画面下に「元に戻す」と「今すぐ完全に削除」が出る。元に戻した標本は、元の標本番号のまま標本一覧に戻る

**S-05 標本詳細の項目**

「この虫が何で、いつ、どこで採れたか」が上から読める順に並べる。

1. **写真**:複数枚はスワイプで切り替える
2. **同定(最新)**:和名、学名、命名者・年、同定者、状態。ラベルに使う内容。「同定を追加」ボタンを置く
3. **標本**:標本番号(未確定のときは「番号未確定」と、「番号を確定」ボタン)、性別、メモ、印刷状態
4. **採集**:採集日(期間)、採集方法、環境・寄主植物
5. **地点**:地名(和・英)、緯度経度、精度、標高。タップすると地図で開く
6. **同定履歴**:過去の同定を、日付、同定者、種名の形で新しい順に表示する

画面下の操作は、編集、同地点で追加、ラベル出力(この1件でS-07を開く)、削除(ごみ箱へ)。編集は専用の編集画面で、座標も直せる(いまの座標を開始地点に、地図の上で選び直す。直すと標高と地名は取り直し、通信できないときは補完待ちに入れる)。

**S-06 同定入力の項目**

- 入力項目:和名(任意)、属・種・亜種、命名者・年(括弧の有無は入力どおり)、同定者(既定は最後に入力した名前)、同定日(既定は今日)、状態
- 状態は半自動とする。種名を入力して保存すると「仮同定」になり、確定したときに自分で「同定済み」に変える。種名が空のときは「未同定」
- 和名または学名を入力すると、辞書(自分が使った種)と甲虫の目録(assets/data/beetles_master.csv。出典は「日本産甲虫目録」)から候補を表示する。候補を選ぶと、和名・学名・命名者・年がまとめて入る
- **候補の一覧**:欄の見出しは「和名」「属名」「種小名」「亜種名」。入力した欄の文字を、候補の同じ欄だけで探す(属名の欄なら属名、種小名の欄なら種小名、亜種名の欄なら亜種名、和名の欄なら和名)。入力済みのほかの欄も、それぞれの欄の条件にする。合う種を、和名の50音順(和名の無い種は最後)に最大20件出し、5件ぶんの高さでスクロールする。名前が長いときは折り返して全体を見せる。20件を超えるときは、総数を示して絞り込みを促す
- **目録からの自動入力**:入力した和名、または属と種(亜種があれば亜種まで)が目録の1つの種に一致したら、空の欄を目録から埋める。入力済みの欄は書き換えない。亜種が複数ある、同じ和名が複数の種に付くなど、1つに決まらないときは入れない。亜種は、入力に無いものを決めつけて入れない。一度自動入力した種は、欄を消されても(全部消し切っても)入れ直さない。「クリア」ボタンで種名の入力をすべて消すと、最初からやり直せる(同定者・同定日は残す)。亜属はラベルに載せないので持たない。亜種の注記(`基亜種`、`九州亜種`など)は和名に残す。和名だけで探すときは、注記を除いた和名でも一致する
- ō ū Ō Ū のボタンを、キーボード上に置く(地名のローマ字の欄)。種名・命名者・年の欄と、同定者の欄の下には、人名に使う特殊文字(マクロン、サーカムフレックス、ウムラウト、ß、アクセント付きの文字、ø å ł š など。`personNameCharacters`)を、小さなボタンで2行に並べる
- 保存すると、上書きせず同定履歴に追加する。ラベルには最新の同定を使う

**S-07 ラベル出力の項目**

画面は上から次の順に並べる。

1. **対象の標本**:選んだ標本の件数と一覧。追加や除外ができる
2. **印刷単位**:「データ+コレクション」「同定のみ」「3種すべて」。「同定のみ」は印刷済みにしない(上記「未印刷のみ」も使わない)
3. **並べ方**:「標本ごとに3枚並べる」(取り違え防止)、「種類ごとにまとめる」
4. **未印刷のみ**:チェックを入れると、印刷済みの標本を除く
5. **プレビュー**:ページ単位で表示し、拡大して確認できる。文字が枠からはみ出すラベルには警告を出す。日本語の地名を省くラベルがあるときは、件数と対象を示して「日本語の地名を省いてよいか」を確認する(第5章)。未同定の標本は同定ラベルを出力せず、除いた件数を表示する
6. **出力**:PDFを作り、共有・保存・印刷に渡す。出力後に「印刷済みにしますか」と確認し、「はい」のときだけ印刷状態を記録する

**大字のローマ字の入力**:大字は取得できたが、そのローマ字が未入力の地点があるときは、画面上部に件数と地点を示し、その場で入力できるようにする(公的データの候補があれば示す)。圏外で記録した初めての場所は、記録画面(S-02)でローマ字を入れられないため。入力した綴りは、その地点と辞書に保存し、同じ大字でローマ字が未入力のほかの地点にも入れる。入力済みの地点の綴りは変えない。PDFを作るときに未入力の地点が含まれていれば、「先に入力する」か「そのまま印刷」かを確認する。記録の正式な修正は、標本詳細(S-05)から記録画面を開いて行う(段階3)

**S-01 地図(ホーム)の項目**

屋外の片手操作を想定して配置する。

- **上部**:左にGPS精度のバッジ(例:±8m)。±30mを超えると警告色にする。その下に、地図のズームレベル(例:Z16)を表示する。右に地名検索(F-20)、地図の切り替えと、補完待ちの件数、下書きの件数(例:下書き 1件)を置く。下書きをタップすると、下から出るシートに一覧を表示し、選んで記録画面(S-02)を開ける。画面は増やさない
- **下部**:中央に大きな「記録」ボタン。端に、現在地に戻るボタンとメニュー(標本一覧、オフライン地図、データ出力、設定)を置く
- **過去地点のピン**:タップすると、ピンの上に吹き出し(日本語の住所と、登録されている和名。件数の多い順に最大4行。和名が無い種は学名、同定が無い標本は「未同定」。入りきらない種は「ほかN種」)を出し、記録ボタンの上にウィンドウを出す。ウィンドウには「この地点で追加」(その地点でいちばん新しい採集の日時・採集方法・環境をコピーして記録画面を開く)と「詳細をひらく」(地点詳細 S-03 を開く)と閉じるボタンを置く。地図の何もない所をタップするか、長押しで新しい位置を指すと、閉じる。吹き出しは、画面の端のピンでも画面の中に収まるよう、横にずらす(先の三角はピンを指したまま)。画面の上の端で上に収まらないときは、ピンの下に出す。位置はタップしたときに決め、そのあと地図を動かしても取り直さない
- **出典**:左下に地理院タイルの出典を常時表示する
- **ピン**:過去の採集地点を表示し、同一地点の標本は1つにまとめて件数を付ける。同一地点は、緯度経度が小数4桁で一致するものとする。縮小すると、近いピンをまとめて表示する(ズーム17以上ではまとめない)。まとめたピンをタップすると、含まれる地点がすべて見えるようにズームインする。未同定の標本を含むピンは色を変える。タップすると地点詳細(S-03)を開く
- **十字と記録の位置**:地図の中央に十字を常時表示する。地図は現在地に追従し(最初の測位後と「現在地に戻る」で追従する)、追従中の「記録」ボタンは現在地(精度つき)で記録画面(S-02)を開く。地図を指で動かすと追従を外し、「記録」ボタンは十字の中央の位置(精度は「手動」)で開く。地図の長押しは、その位置に仮ピンを立て、「ここで記録」で記録画面を開く。記録する位置の近くに過去のピンがあるときは、「この地点に追加」と「新しい地点」を選べる
- **測位中**:「測位中…」と表示する。追従中に位置が未確定のまま記録するときは、確認を出す(地図の中心で記録する)
- **圏外**:「オフライン」と表示する。保存範囲の外はタイルが無いため、灰色で表示する

**S-08 オフライン地図の項目**

*一覧(最初の画面)*

- 上部に、使用中の容量と上限を表示する(例:320MB / 1GB)。全体の上限は既定1GBの固定で、設定で変更できる
- 保存済みエリアを、名前、地図の種類、最大ズーム、容量、保存日の順に並べる。保存から半年たったエリアには「更新」の印を付ける
- エリアをタップすると、地図で範囲を確認でき、「更新」と「削除」ができる
- 下部に「新しいエリアを保存」ボタンを置く

*新しいエリアの保存*

1. **範囲の指定**:地図を動かし、画面中央の枠をドラッグで広げ縮めする。「現在地の周辺」ボタンで、現在地を中心に枠を置ける。「地名検索」ボタン(F-20)で、検索した場所の周辺に枠を置ける
2. **地図の種類**:標準地図、淡色地図、写真、陰影起伏、色別標高図から複数選べる。既定は標準地図
3. **最大ズーム**:スライダーで選ぶ。既定は16で、上限は地図ごとに決まる
4. **見積もり**:枚数と容量を、変更のたびに表示する。1エリアの上限(既定200MB)を超えると赤字で警告し、保存できない
5. **名前**:地名から自動で付ける(例:魚沼市周辺)。編集できる
6. **保存**:Wi-Fiに接続していないときは、確認を出す

*ダウンロード中*

- 進捗(枚数)を表示し、バックグラウンドでも続ける
- 圏外や中断で止まったときは、続きから再開できる
- 取得は低速で行う(利用規約の確認が取れるまでの対策)

**S-09 データ出力の項目**

*CSV出力*

- 範囲:全件、絞り込み中の結果、選択した標本から選ぶ
- 列:第4章のDarwin Coreの列に、和名(`vernacularName`)を加える。1行が1標本
- 文字コード:UTF-8(BOM付き)。Excelで開いても日本語が崩れない
- 写真:CSVには含めず、ファイル名の列だけを出力する
- 出力先:端末の共有画面から、保存先やアプリを選ぶ

*バックアップ*

- 全データを1つのファイルにまとめて書き出す。ファイル名に日付を付ける(例:`konchu-backup-20261003`)
- 写真を含めるかを選べる(既定は含める)。含めるとファイルが大きくなる
- 保存先は共有画面から選ぶ(iCloud Drive、Google Driveなど)
- 最後のバックアップから30日以上たつと、地図画面に小さく通知する

*復元*

- バックアップのファイルを選び、中身(標本数、期間)を確認してから実行する
- 方式は「置き換え」のみとする。機種変更や初期化後に使う
- 実行前に、現在のデータを自動でバックアップする
- 「統合」(標本番号が同じものを除いて追加)は、将来機能とする

**S-11 設定の項目**

設定項目を、6つのグループにまとめる。

| グループ | 項目(既定値) |
| --- | --- |
| 採集者 | 採集者名(英語表記。ラベルは `K. YOSHIHARA` の形で印字)、同定者名の既定(最後に入力した名前) |
| 標本番号 | 接頭辞(`KYC`)、桁数(5)、開始番号(初回のみ) |
| 記録 | 標高の丸め(10m/1m、既定10m)、GPS精度の警告しきい値(±30m)、採集方法の追加・並べ替え |
| ラベル | 用紙(はがき)、ラベル寸法(幅15×高さ10mm)、文字サイズ(4〜5pt)、余白、切り取り線の有無 |
| 地図・データ | オフライン地図の容量上限(全体1GB、1エリア200MB)、ごみ箱の保持期間(30日)、バックアップ通知(30日)、辞書管理(S-10)を開く |
| アプリ情報 | 出典と加工の表記(地理院タイル、標高API、全国地方公共団体コード、郵便番号データ、アドレス・ベース・レジストリ)、バージョン |

- 開始番号は初回の設定だけで、以降は変更できない。次の番号は自動で進める
- 接頭辞と桁数は、番号を使い始めた後も変更できる。既存の標本番号は変わらない

**S-10 辞書管理の項目**

地名、種、環境・寄主植物の候補を、タブで切り替えて編集する。候補は、記録や同定で入力したときに自動で溜まる。

- **共通の操作**:検索、追加、編集、削除、統合(重複した候補を1つにまとめる)。各候補に、使用している標本の件数を表示する。行をタップして編集し、長押しで複数を選んで削除・統合する。タブは「地名」「種」「環境」「寄主植物」の4つ
- **地名**:和文地名(市町村+大字)と、大字のローマ字を持つ。県・市町村の英語表記は内蔵の対応表を使い、編集しない。地名は、大字ごとに1件で重複しないので、追加と統合は無い(ローマ字の編集と削除のみ)
- **種**:和名、属、種、亜種、命名者・年を、1セットで持つ。学名は斜体で表示する。括弧の有無は命名者・年の入力どおり保持する
- **環境・寄主植物**:文字列のみ。環境と寄主植物は、種別を分けて持つ
- **既存の標本への影響**:辞書を変更しても、保存済みの標本は変わらない。反映したい場合は、標本一覧の一括編集を使う
- **バックアップ**:辞書もバックアップに含める

| 採集 | どの地点か、採集日(期間)、採集方法、光源やベイト、環境・寄主植物、採集者 |

## 13. 補完待ちの動作

圏外で取得できなかった標高と地名を、通信が戻ったときに補完する。

- **補完のタイミング**:通信が戻ったとき、アプリを開いたとき・前面に戻ったとき(自動)、地図画面の「補完待ち」をタップしたとき(手動で「今すぐ補完」)。iPhoneはアプリが閉じているときの通信に制限があるため、主なタイミングは「アプリを開いたとき」になる
- **失敗時の再試行**:通信エラーは、自動で3回再試行する(1分後、5分後、30分後)。その後は、次のきっかけを待つ。通信は成功したが、データが無いとき(海上など)は、失敗とは扱わず「取得不可」として記録し、手入力できる
- **印刷済みラベルとの食い違い**:ラベルを出力するとき、ラベルに載せた元の標高(設定の丸め後)と地名(国・県・郡・市町村・大字の英語表記と、郡・市町村・大字の和文)を、標本ごとに保存する。改行や日本語地名の省略を経る前の値を残すので、省略しただけでは食い違いにならない。のちに補完や修正で値が変わり、保存した値と食い違ったときは、標本に「ラベルと不一致」の印を付ける(標本一覧の行、標本詳細、ラベル出力)。標本一覧で、印の付いた標本だけを絞り込める。ラベル出力の「未印刷のみ」は、食い違った標本も再印刷の対象にする。古い形式(印字した文字列)で保存した地名は、元の値が分からないので比べない(標高は比べる)
- **補完待ちのまま印刷**:許す。補完待ちの標本を含めて印刷しようとしたときは、「標高・地名が未取得の標本が3件」と警告し、「そのまま印刷」か「補完してから印刷」を選べる。そのまま印刷した標本は、補完後に「ラベルと不一致」になり、再印刷を促す。未取得の標高と地名は、ラベルから省いて印字する(例:標高が無ければ \`(alt. … m)\` を出さない)。空欄は残さない

## 14. 標本番号の採番と下書き

**採番**

- 記録を保存した標本には、番号を付けない(番号未確定=仮)。個体数などを入力したあとに直すことが多いため、番号は、確定の操作で付ける。保存では、採集と標本(作成数ぶん)を、1回でまとめて書き込む。途中でアプリが落ちても、全部が保存されるか、全部が無かったことになる
- 確定の操作は、標本一覧で選んだ標本(画面下の「番号確定」)、標本詳細の「番号を確定」(この標本だけ、またはこの採集の未確定の標本すべて)、ラベル出力のときの案内、の3つ。確定すると、番号が未確定の標本に、保存した順(作成日時、同じならID)に、続きの番号を付け、次の番号を進める。確定済みの標本とごみ箱の標本は、変えない。確定した番号は戻せない
- 番号は確定するまで使わないので、仮の標本を削除したり、個体数を変えたりしても、欠番にならない
- 仮の標本は、標本一覧・標本詳細・ごみ箱で「番号未確定」と表示する。個体数は、仮の標本の編集で増減できる(増やすと仮の標本を足す。減らすと、保存した順の新しい標本から削除する。同定を入力した標本と、編集中の標本は、減らさない)
- ラベル出力で、番号が未確定の標本があり、コレクションラベルを出すときは、「番号を確定して出力するか」を確認する(「やめる」なら確定しない)。同定ラベルだけを出すときは、番号が要らないので聞かない。データラベルは番号を印字しない
- 新規の記録画面には、「番号は確定時に決まります」と表示する
- 保存前に画面を閉じたときは、番号を使っていないので、戻す処理は要らない
- 確定した番号は、完全に削除されても欠番のままにし、再利用しない。確定のとき、書式を変えたことで、既存の標本番号と同じ文字列になる番号は飛ばす
- 開始番号は、初回の起動時に「これまでの最新番号」を入力させる(標本が無ければ0)。入力するまで、記録は始められない。次の番号は、入力した番号+1から始まる
- 「番号を指定」(過去標本の登録)は、確定済みで保存する。画面の作成は、まだ(保存の処理には、保存と同時に確定する指定がある)

**下書き**

- 記録を途中で中断して、別の標本を登録できる。下書きには番号を付けず、保存した標本は番号未確定(仮)になり、確定した順に番号が付く
- 下書きを開いたときも、「番号は確定時に決まります」と表示する。「番号を指定」で入力した番号は、保存時に重複を確認する
- 記録画面を閉じるときは、何か入力していれば、確認を出す。選択肢は「下書きに保存」「破棄」「続ける」。何も入力していないときは、確認せず閉じる
- 地図画面の上部に、補完待ちと並べて「下書き 1件」を表示する。タップすると、一覧から選んで記録画面を開ける
- 位置と日時は、下書きにした時点の値を保存し、再開しても変わらない
- 下書きは、標本一覧、ラベル出力、CSVには出ない。保存して初めて標本になる
